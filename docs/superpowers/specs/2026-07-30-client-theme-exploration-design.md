# Client Theme Exploration Design

วันที่: 30 กรกฎาคม 2026  
สถานะ: อนุมัติทิศทางแล้ว รอสร้าง prototype

## เป้าหมาย

สร้าง mockup หน้าแรกฝั่ง client จำนวน 4 แบบ เพื่อเปรียบเทียบภาพลักษณ์ใหม่ของ
วัดหลวงพ่อใสอย่างเป็นธรรม แต่ละแบบต้องตอบโจทย์เดียวกันด้วยโครงสร้าง บุคลิก สี
ตัวอักษร และจังหวะการเล่าเรื่องที่แตกต่างกันจริง ไม่ใช่เพียงเปลี่ยน palette

ผลลัพธ์รอบนี้ใช้เพื่อเลือก design direction เท่านั้น ยังไม่เปลี่ยนหน้า production
และยังไม่ออกแบบทุกหน้าของเว็บไซต์

## ผู้ใช้และผลลัพธ์ที่ต้องการ

ผู้ชมหลักคือชาวไทย ชาวเยอรมัน และผู้สนใจทั่วไปในเยอรมนี ทั้งผู้ที่คุ้นเคยกับวัด
และผู้ที่เพิ่งเริ่มสนใจ ภายใน 10 วินาทีแรก ผู้ชมควรเข้าใจว่าเว็บไซต์นี้เป็นพื้นที่
แห่งการปฏิบัติเพื่อความสงบและความสุขที่แท้จริง จากนั้นต้องเห็นก้าวต่อไปที่ทำได้จริง:

1. ดูกิจกรรมและเข้าร่วมปฏิบัติธรรม
2. วางแผนการเดินทางมาวัด
3. ทำความรู้จักวัดและแนวทางปฏิบัติ
4. สนับสนุนวัดเมื่อยังมาเข้าร่วมด้วยตนเองไม่ได้

## ขอบเขตของ mockup

แต่ละแบบเป็นหน้าแรกเต็มหน้าและมีส่วนประกอบเดียวกัน เพื่อให้การเปรียบเทียบไม่ถูก
บิดเบือนด้วยปริมาณเนื้อหาที่ต่างกัน:

- Navigation พร้อมตัวเลือกภาษาไทย อังกฤษ และเยอรมัน
- Hero พร้อมข้อความหลักและ CTA สองระดับ
- ส่วนแนะนำวัดและแนวทางปฏิบัติ
- กิจกรรมที่กำลังจะมาถึง
- ข้อมูลเตรียมตัวและการเดินทาง
- ส่วนสนับสนุนวัด
- Footer พร้อมช่องทางติดต่อ

ใช้เนื้อหาภาษาไทยที่สมจริงใน prototype และทดสอบพื้นที่สำหรับข้อความเยอรมันที่ยาว
กว่า แม้ยังไม่ต้องสร้างสำเนา mockup แยกครบทั้งสามภาษาในรอบนี้

## ข้อกำหนดร่วม

- ใช้เฉพาะภาพจริงที่มีอยู่ใน `frontend/public/images/gallery/`
- ห้ามใช้ภาพจำลอง ภาพ stock หรือภาพสร้างใหม่
- หลีกเลี่ยงภาพ `hero-bg.*` และ `gallery/1.png`–`gallery/6.png` ซึ่งมีลักษณะ
  เป็นภาพสร้าง ไม่ใช่หลักฐานจริงของสถานที่
- ใช้ภาพเพื่อสร้างความน่าเชื่อถือ ไม่ใช้สัญลักษณ์ศาสนา สีทอง หรือลายไทยเป็นของตกแต่ง
  ซ้ำ ๆ
- CTA หลักคือ “ดูกิจกรรมและเข้าร่วมปฏิบัติธรรม”
- CTA รองคือ “วางแผนการเดินทางมาวัด”
- ปุ่มและองค์ประกอบโต้ตอบต้องมี touch target อย่างน้อย 44px
- เนื้อหาต้องอ่านได้โดยไม่พึ่ง animation และรองรับ `prefers-reduced-motion`
- ตัวอักษรและสีต้องมุ่งสู่ WCAG 2.2 AA

## Direction 1: ร่มไม้ก่อนเข้าศาลา

**แกน:** immersive, contemplative, narrative

ผู้ชมรู้สึกถึงความสงบก่อนรับข้อมูล ใช้ภาพจริงขนาดใหญ่ โทนเขียวลึกกับเขียวอ่อน
สว่าง และจังหวะเนื้อหาที่มีช่วงพัก Hero พาผู้ชมเข้าสู่เรื่องราว ก่อนค่อยเปิดเผย
กิจกรรม การเตรียมตัว และการเดินทาง

- Layout: full-bleed image, เนื้อหาเรียงเป็นฉากยาว, ใช้พื้นที่ว่างแบ่งจังหวะ
- Typography: display ที่มีบุคลิกสุขุม จับคู่กับ body ที่อ่านง่ายหลายภาษา
- Color strategy: drenched deep forest พร้อม accent เขียวอ่อนที่ใช้เฉพาะ action
- Motion: การเปิดหน้าแบบ reveal ครั้งเดียวและการเปลี่ยนภาพอย่างนุ่มนวล
- จุดแข็ง: ถ่ายทอดความสงบและเป้าหมายการปฏิบัติได้ชัดที่สุด
- ต้นทุน: คุณภาพขึ้นกับการครอปและการเรียงภาพจริงอย่างมาก

## Direction 2: วัดที่มีชีวิต

**แกน:** welcoming, community, action first

ให้ผู้มาใหม่เห็นกิจกรรม เวลา วิธีเข้าร่วม และสิ่งที่ต้องเตรียมก่อนเรื่องเล่ายาว
ใช้ภาพกิจกรรมจริงกับสีฟ้าเข้ม เหลืองสด และพื้นขาว เพื่อสื่อความเปิดกว้างและ
การมีส่วนร่วมโดยไม่ดูเชิงพาณิชย์

- Layout: activity-led homepage, schedule strip, ข้อมูลสำคัญสแกนได้เร็ว
- Typography: humanist sans ที่เป็นมิตรและรองรับสามภาษา
- Color strategy: full palette ที่จำกัดบทบาทชัดเจน
- Motion: feedback สั้น ๆ ที่ปุ่มและรายการกิจกรรม ไม่มี motion เพื่อการตกแต่ง
- จุดแข็ง: เหมาะกับผู้มาใหม่ ครอบครัว และผู้ที่เข้ามาหาข้อมูลเชิงปฏิบัติ
- ต้นทุน: บรรยากาศขรึมและการใคร่ครวญน้อยกว่าแนวแรก

## Direction 3: สำนักปฏิบัติร่วมสมัย

**แกน:** architectural, precise, quietly bold

ใช้โครงสร้างไม่สมมาตร สีไวน์เข้ม เทาหิน และส้มแดง ภาพถ่ายทำหน้าที่เป็นหลักฐาน
เชิงสารคดีมากกว่าภาพสร้างบรรยากาศ ตัวอักษร sans และเส้นโครงสร้างทำให้เว็บไซต์
รู้สึกร่วมสมัยโดยไม่เลียนแบบเว็บวัดทั่วไป

- Layout: asymmetric composition, ภาพและข้อมูลวางแบบ architectural
- Typography: sans ที่สุขุม น้ำหนักและขนาดสร้างลำดับชัดเจน
- Color strategy: committed wine surface พร้อม oxide accent
- Motion: masked reveal เฉพาะจุดสำคัญและ transition ที่กระชับ
- จุดแข็ง: มีภาพจำชัดและแตกต่างจากหมวดเว็บไซต์วัด
- ต้นทุน: อาจรู้สึกจริงจังและเย็นสำหรับผู้ชมบางกลุ่ม

## Direction 4: หนึ่งภาพ หนึ่งลมหายใจ

**แกน:** essential, spacious, quietly human

Minimal ที่ไม่ใช่เพียงพื้นขาวโล่ง ใช้พื้นขาวจริง สีหมึก และสีน้ำเงินลาพิสเพียง
จุดเดียว หนึ่งภาพจริงทำหน้าที่ต่อหนึ่งช่วงเนื้อหา ไม่มี card grid และไม่มีของตกแต่ง
ที่ไม่ช่วยการอ่าน

- Layout: single-column rhythm, เส้นแบ่งบาง, ภาพหนึ่งภาพต่อหนึ่งประเด็น
- Typography: เรียบแต่มี scale ชัดเจน รองรับข้อความไทยและเยอรมัน
- Color strategy: restrained neutral พร้อม lapis accent ไม่เกิน 10% ของพื้นผิว
- Motion: แทบไม่มี entrance motion เน้น state transition ที่จำเป็น
- จุดแข็ง: อ่านง่าย สงบ และขยายไปยังหน้าภายในได้ตรงไปตรงมา
- ต้นทุน: พลังด้านอารมณ์และความโดดเด่นน้อยกว่าแนวอื่น

## Prototype Architecture

สร้าง prototype เป็นพื้นที่แยกจาก production ภายใต้ route หรือ harness สำหรับ
theme exploration โดยมี:

- ไฟล์หนึ่งชุดต่อหนึ่ง direction
- ตัวสลับแบบคงที่เพื่อเปลี่ยนดูทีละแบบเต็มขนาด
- เนื้อหาชุดเดียวกันทุก direction
- ไม่ import prototype กลับเข้าสู่ production components
- ไม่เรียก API จริงและไม่เปลี่ยน CMS contract
- ไม่แก้ design tokens ส่วนกลางจนกว่าจะเลือกผู้ชนะ

ตัวสลับต้องรองรับการคลิกและคีย์บอร์ด การเปลี่ยน direction ต้องเกิดทันทีโดยไม่มี
animation เพื่อให้สลับเปรียบเทียบซ้ำได้รวดเร็ว

## Responsive และ Accessibility

ตรวจอย่างน้อยที่ความกว้าง 390px, 768px และ 1440px โดยต้อง:

- ไม่มีหัวข้อหรือปุ่มล้นเมื่อใช้ข้อความเยอรมันจำลอง
- Navigation และ CTA ใช้งานด้วยคีย์บอร์ดได้
- Focus indicator มองเห็นชัด
- สีข้อความหลักผ่าน contrast 4.5:1 และข้อความขนาดใหญ่ผ่าน 3:1
- เนื้อหาสำคัญไม่ซ่อนอยู่หลัง hover หรือ animation
- เมื่อเปิด reduced motion ยังเห็นเนื้อหาครบและเข้าใจลำดับได้

## การตรวจรับ prototype

- ทั้ง 4 direction เปิดดูได้จากตัวสลับเดียว
- ทุก direction แสดงหน้าแรกเต็มหน้าและใช้เนื้อหาชุดเดียวกัน
- ภาพทั้งหมดมาจากชุดภาพจริงในโปรเจกต์
- ปุ่มและ navigation จำลองตอบสนองได้ ไม่มี dead control ที่ทำให้เข้าใจผิด
- ไม่มี error ใน browser console
- ผ่าน lint และ type-check หาก prototype อยู่ใน Next.js
- มีภาพ screenshot desktop และ mobile ของทุก direction เพื่อช่วยตัดสินใจ

## สิ่งที่ไม่ทำในรอบนี้

- ไม่แทนที่หน้าแรก production
- ไม่ redesign หน้า about, events, gallery, contact หรือหน้ารายละเอียด
- ไม่เปลี่ยน API, CMS schema, localization contract หรือ backend
- ไม่เพิ่ม dependency หากเครื่องมือเดิมรองรับ prototype ได้
- ไม่เลือกหรือ promote direction ใดจนกว่าผู้ใช้จะตัดสินใจหลังดู mockup
